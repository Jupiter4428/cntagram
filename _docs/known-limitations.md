# ข้อจำกัดของระบบและงานที่กำลังพัฒนาต่อ (Known Limitations & Upcoming Work)

ระบบรุ่นปัจจุบันบน Production ([https://cntagram-h195.onrender.com/](https://cntagram-h195.onrender.com/)) มีข้อจำกัดและรายการที่กำลังพัฒนาต่อดังนี้  
แต่ละข้อมี User Story / Issue อ้างอิงอยู่ใน [Product Backlog](./requirements.md)

เมื่อปิด story ที่เกี่ยวข้อง ให้ลบข้อนั้นออกจากไฟล์นี้ใน PR เดียวกัน

## บัญชีผู้ใช้

- **ไม่ยืนยันว่าเป็นเจ้าของอีเมลจริง**: ตอนสมัครระบบตรวจแค่รูปแบบ `<รหัสนักศึกษา>@student.tu.ac.th` ใครรู้รหัสของเพื่อนก็สมัครแทนได้ ระบบยังไม่ส่งอีเมลใดๆ (`MAILERS` ตั้งเป็น console backend ซึ่งพิมพ์อีเมลลง terminal) (US-14, SP-2)
- **ศิษย์เก่าเข้าระบบไม่ได้หลังอีเมลมหาวิทยาลัยถูกปิด**: ยังผูกอีเมลส่วนตัวกับบัญชีไม่ได้ (US-15)
- **การลบบัญชี**: มีหน้า `/account/delete/` สำหรับผู้ใช้ที่ล็อกอินแล้ว (US-13); การลบใช้การ anonymize ข้อมูล (`User.anonymize()`) แทนการลบแถวจริงเพื่อรักษาความสัมพันธ์ข้อมูลและประวัติการอัปโหลด
- **ระงับผู้ใช้ได้แค่ปิด `is_active` ในฐานข้อมูล**: ไม่มีเหตุผล ระยะเวลา หรือบันทึกว่าใครระงับ (US-16)
- **การจำกัดอัตราการเข้าสู่ระบบร่วมกันหลัง IP/NAT เดียวกัน (Shared IP Rate Limiting)**: ถัง IP ของ Two-bucket login rate limit นับความล้มเหลวรวมจาก IP เดียวกัน 100 ครั้งต่อ 5 นาที (`LOGIN_RATE_LIMIT_IP_ATTEMPTS = 100`) เพื่อป้องกันการโจมตีแบบ Password Spraying ข้ามบัญชี หากมีการพยายามเข้าสู่ระบบผิดเกิน 100 ครั้งจาก IP เดียวกัน ผู้ใช้ทุกคนที่อยู่หลัง IP นั้น (เช่น Wi-Fi หรือ NAT ของมหาวิทยาลัย) จะได้รับ HTTP 429 ชั่วคราว แม้จะใส่รหัสผ่านถูกต้องก็ตาม จนขึ้นช่วง 5 นาทีถัดไป (รอไม่เกิน 5 นาที) (Issue #172)
  ข้อแลกเปลี่ยน: เพดาน 100 ทำให้ IP เดียวเดารหัสข้ามบัญชีได้มากกว่าเดิม 5 เท่า และเพราะนับเป็นช่วงเวลาคงที่ (fixed window) ช่วงที่คร่อมขอบเวลาจะเดาได้สูงสุด 2 เท่าของเพดาน (บัญชีเดียว 10 ครั้ง, IP เดียว 200 ครั้ง)

## ภาควิชา รุ่น และรายวิชา

- **การนำเข้าไฟล์จำนวนมาก (US-17)**: รองรับการนำเข้าไฟล์เดิมจำนวนมาก (Bulk Import) ผ่าน CSV ทั้งทาง Management Command (`python manage.py import_documents`) และหน้าเว็บ Super Admin พร้อมโหมดทดลองรัน (dry run) และตรวจข้ามไฟล์ซ้ำ (SHA-256) เรียบร้อยแล้ว
- **รุ่นจุดตัดของข้อสอบรุ่นเก่ามีค่าเดียวทั้งระบบ** (`legacy_batch_max` = 23) ใช้กับทุกภาค แม้เลขรุ่นของแต่ละภาคเริ่มคนละปี (US-18)
- **อัปโหลดวิชาที่ยังไม่ผูกกับรุ่นไม่ได้** และไม่มีช่องทางขอให้ Super Admin เพิ่มวิชา (US-19)
- **ระบบไม่รู้ว่าผู้ใช้อยู่รุ่นไหน**: ยังไม่มีกฎจับคู่ปีเข้ากับเลขรุ่นของแต่ละภาค (US-20)

## เอกสารและการจัดเก็บไฟล์

- **แก้ไขหลังอัปโหลด (กำลังพัฒนา)**: ปัจจุบันเจ้าของยังส่งเวอร์ชันใหม่ แก้คำอธิบาย หรือลบเอกสารของตัวเองไม่ได้ (กำลังพัฒนาใน US-21 / Issue [#217](https://github.com/Jupiter4428/cntagram/issues/217)) ส่วนความสามารถให้ Moderator และ Super Admin ซ่อนเอกสารที่เผยแพร่แล้วแต่มีปัญหา กำลังอยู่ในขั้นตอนรีวิว (US-25 / Issue [#216](https://github.com/Jupiter4428/cntagram/issues/216), PR [#227](https://github.com/Jupiter4428/cntagram/pull/227))
- **ไม่สแกนไวรัส**: ระบบตรวจแค่ MIME, magic bytes `%PDF-` และตรวจไฟล์ซ้ำด้วย SHA-256 (US-12) ส่วน `scan_status` ค้างเป็น `pending` ตลอด PDF ที่ฝัง JavaScript จึงผ่านได้ ด่านที่มีคือ Moderator ตรวจก่อนเผยแพร่ (US-24 สแกนไวรัส, SP-1)
- **Ephemeral Filesystem บน Render Free Tier**: การรันบน Render Free Plan ไม่มี Persistent Disk ทำให้ไฟล์ PDF ที่อัปโหลดไว้ใน `media/vault/` จะถูกล้างเมื่อคอนเทนเนอร์ Redeploy หรือหมุนรอบใหม่ (แม้แถวข้อมูลใน PostgreSQL ยังอยู่) ดูแนวทางแก้ไขและสำรองข้อมูลใน [ADR 0005](./adr/0005-production-deployment-and-backup.md) และ [`backup-operations.md`](./backup-operations.md) (Issue [#192](https://github.com/Jupiter4428/cntagram/issues/192))
- **ไม่มีหน้ารวมข้อสอบรุ่นเก่า** ให้ Super Admin ตรวจหรือเอาลงหลังเผยแพร่แล้ว (US-27)

## การค้นหา

- ค้นได้ด้วยรหัสวิชาแบบตรงตัว (พร้อมตัวกรองภาควิชา รุ่น ประเภทเอกสาร ช่วงสอบ และปี พ.ศ. ตาม US-11) แต่ยังไม่มีแท็กหรือค้นจากหัวข้ออิสระ (US-23)
- ผลค้นหาเรียงตายตัว ภาค → รุ่น → ใหม่สุด ยังเรียงตามยอดดาวน์โหลดหรือคะแนนไม่ได้ แต่ระบบมีการบันทึกประวัติการดาวน์โหลดผ่าน `DownloadLog` แล้ว (US-28, US-8)

## ชุมชน เว็บบอร์ด และการร้องเรียน

- **กระดานสนทนาเว็บบอร์ด (`webboard`)**: มีระบบตั้งกระทู้ ตอบกลับ ปักหมุด/ล็อก/ลบ อีโมติคอน MSN และฝังภาพ GIF แล้ว (PR #202, #226) ส่วนการแก้ไขกระทู้/ข้อความตอบกลับ (Issue [#212](https://github.com/Jupiter4428/cntagram/issues/212)), การแบ่งหน้า Pagination และ View Debounce (Issue [#211](https://github.com/Jupiter4428/cntagram/issues/211)), และการป้องกันการแปลงอีโมติคอนซ้อนในคำ/URL (Issue [#213](https://github.com/Jupiter4428/cntagram/issues/213), [#209](https://github.com/Jupiter4428/cntagram/issues/209)) กำลังพัฒนาต่อ
- **คอมเมนต์และให้คะแนนใต้เอกสารโดยตรง**: ยังไม่มีคอมเมนต์หรือการให้ดาว 1–5 ดาวใต้หน้าเอกสารแต่ละชิ้นโดยตรง (US-29, US-30, US-31) แต่มีกระดานสนทนาเว็บบอร์ดที่ผูกกับรายวิชา (`Thread.course`) และ Shoutbox/โพลหน้าแรกแทน
- **ช่องทางร้องเรียนในระบบ (กำลังพัฒนา)**: ปุ่มรายงานเอกสารที่มีปัญหา (US-32 / Issue [#218](https://github.com/Jupiter4428/cntagram/issues/218)), แบบฟอร์มสาธารณะให้เจ้าของลิขสิทธิ์ที่ไม่มีบัญชีแจ้งลบ (US-33 / Issue [#219](https://github.com/Jupiter4428/cntagram/issues/219)), และหน้าให้ Super Admin ตัดสินเรื่องร้องเรียน (US-35 / Issue [#220](https://github.com/Jupiter4428/cntagram/issues/220)) กำลังอยู่ระหว่างการพัฒนา
