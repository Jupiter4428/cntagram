### คำอธิบาย System Context (Level 1):
1. **ผู้ใช้งานที่ระบบรองรับจริงในปัจจุบัน (Active Users):**
   - **Guest**: เข้าได้เฉพาะหน้าสมัครสมาชิกและเข้าสู่ระบบ หน้าอื่นทั้งหมดต้องล็อกอินก่อนเข้าใช้งานเนื่องจากระบบเปิด `LoginRequiredMiddleware`
   - **Student / Alumni**: สมัครสมาชิกด้วยอีเมล `@student.tu.ac.th` และรหัสผ่าน ทำหน้าที่อัปโหลดเอกสารใหม่ ดาวน์โหลดไฟล์ และจัดการโปรไฟล์
   - **Moderator**: ตัวแทนนักศึกษาประจำภาควิชาที่ได้รับสิทธิ์ ทำหน้าที่ตรวจคัดกรอง อนุมัติ หรือปฏิเสธเอกสารของภาคตนเอง
   - **Super Admin**: ผู้ดูแลระบบ มีสิทธิ์แต่งตั้ง/ถอดถอน Moderator และเข้าถึง Django Admin
2. **ระบบและส่วนที่ยังไม่ได้สร้างใน v1.0.0 (เส้นประ):**
   - **อาจารย์ / เจ้าของลิขสิทธิ์**: ฟอร์มสาธารณะสำหรับแจ้งละเมิดลิขสิทธิ์ (อยู่นอกขอบเขต MVP v1.0.0)
   - **Email Service**: ระบบส่งอีเมลแจ้งเตือนอัตโนมัติ (ข้ามไปทำในเวอร์ชันถัดไปตามข้อตกลง SP-2)

### คำอธิบาย Container Level (Level 2):
1. **Web Browser (Client Layer):** ผู้ใช้เข้าชมผ่านเว็บเบราว์เซอร์ด้วยอินเทอร์เฟซ Bootstrap 5 รองรับ Responsive Design บนทุกอุปกรณ์
2. **Render Edge Router / Reverse Proxy:** รับคำขอ HTTPS จากอินเทอร์เน็ต ทำ TLS Termination และส่งต่อคำขอผ่าน Internal Network ไปยัง Web Container
3. **Gunicorn WSGI Server:** ทำหน้าที่เป็น WSGI HTTP Server สำหรับรันโปรเซสของ Django ในสภาพแวดล้อม Production
4. **Middleware Pipeline:** จัดการความปลอดภัยตามลำดับ: `SecurityMiddleware` → `WhiteNoiseMiddleware` (เสิร์ฟไฟล์สถิตที่บีบอัดและมี cache hash) → `SessionMiddleware` → `CsrfViewMiddleware` → `AuthenticationMiddleware` → `LoginRequiredMiddleware` → `XFrameOptionsMiddleware`
5. **Django Application & Apps Structure:**
   - สถาปัตยกรรมแบบ **Modular Monolith** แบ่ง App ตาม Bounded Context โดยมีทิศทาง Dependency ทางเดียว `catalog` ← `accounts` ← `materials` ([ADR 0001](../adr/0001-modular-monolith-and-app-boundaries.md))
   - ทุก App แยกชั้นการทำงานด้วย **Service Layer** และ **Selectors** ([ADR 0002](../adr/0002-service-layer-and-selectors.md))
   - ตารางอนุมัติ (`Approval`, `DocTypeRequiredRole`) อยู่ในแอป `materials` ตาม [ADR 0004](../adr/0004-approval-tables-in-materials.md)
   - แอป `accounts` จัดการ `User`, `Role`, `UserRole` และนับการจำกัดอัตรา (Rate Limit) ผ่าน Django cache (`accounts/services.py`)
6. **Managed PostgreSQL Database:** ฐานข้อมูลเชิงสัมพันธ์หลักบน Render (Region: Singapore) เชื่อมต่อผ่าน Internal Database URL เพื่อความปลอดภัยและความเร็วสูงสุด
7. **Persistent Disk (Protected PDF Vault):** ที่จัดเก็บไฟล์เอกสาร PDF จริง โดยยึดหลัก [ADR 0003](../adr/0003-document-storage-and-protected-preview.md) คือ **ไม่ตั้ง `MEDIA_URL`** และไม่มี Direct URL เข้าถึงไฟล์ การเปิดอ่าน (Preview) และดาวน์โหลดต้องผ่านการตรวจสอบสิทธิ์ใน View ของ Django เสมอ
8. **Backup Strategy:** แผนสำรองข้อมูลประจำวัน (Daily Snapshot บน Managed DB ควบคู่กับการทำ Logical Dump `pg_dump` และ Media Vault `tar.gz` ผ่านสคริปต์ `scripts/backup_restore.sh`) ตามข้อตกลงใน [ADR 0005](../adr/0005-production-deployment-and-backup.md)
9. **เส้นประ (External Integrations):** ระบบส่งอีเมล (SP-2) และการสแกนไวรัสไฟล์อัปโหลด (SP-1 / US-24) ยังคงเป็นเส้นประเนื่องจากอยู่นอกกรอบเวลาของ v1.0.0
