## Level 1: System Context Diagram

แสดงขอบเขตของระบบ CNtagram และผู้ใช้งานประเภทต่างๆ ที่ระบบรองรับจริงในปัจจุบัน

### คำอธิบาย System Context (Level 1):
- **Guest**: เข้าได้เฉพาะหน้าแรก หน้าสมัครสมาชิก และหน้าเข้าสู่ระบบ หน้าอื่นทั้งหมดต้องล็อกอินก่อนเข้าใช้งานเนื่องจากระบบเปิด `LoginRequiredMiddleware`
- **Student / Alumni**: สมัครสมาชิกด้วยอีเมล `@student.tu.ac.th` และรหัสผ่าน ทำหน้าที่อัปโหลดเอกสารใหม่ ค้นหาและดาวน์โหลดไฟล์ ร่วมกิจกรรมเว็บบอร์ด/วิดเจ็ตหน้าแรก และจัดการบัญชีตนเอง (`/account/delete/`)
- **Moderator**: ตัวแทนนักศึกษาประจำภาควิชาที่ได้รับสิทธิ์ ทำหน้าที่ตรวจคัดกรอง อนุมัติ หรือปฏิเสธเอกสารของภาคตนเอง รวมถึงดูแลกระทู้ในเว็บบอร์ด
- **Super Admin**: ผู้ดูแลระบบส่วนกลาง มีสิทธิ์จัดการภาควิชา รุ่น รายวิชา แต่งตั้ง/ถอดถอน Moderator อนุมัติเอกสาร และเข้าถึง Django Admin

### คำอธิบาย Container Level (Level 2):
1. **Web Browser (Client Layer):** ผู้ใช้เข้าชมผ่านเว็บเบราว์เซอร์ด้วยอินเทอร์เฟซ Bootstrap 5 รองรับ Responsive Design บนทุกอุปกรณ์
2. **Render Edge Router / Reverse Proxy:** รับคำขอ HTTPS จากอินเทอร์เน็ต ทำ TLS Termination และส่งต่อคำขอผ่าน Internal Network ไปยัง Web Container
3. **Gunicorn WSGI Server:** ทำหน้าที่เป็น WSGI HTTP Server สำหรับรันโปรเซสของ Django ในสภาพแวดล้อม Production
4. **Middleware Pipeline:** จัดการความปลอดภัยตามลำดับ: `SecurityMiddleware` → `WhiteNoiseMiddleware` (เสิร์ฟไฟล์สถิตที่บีบอัดและมี cache hash) → `SessionMiddleware` → `CsrfViewMiddleware` → `AuthenticationMiddleware` → `LoginRequiredMiddleware` → `XFrameOptionsMiddleware`
5. **Django Application & Apps Structure:**
   - สถาปัตยกรรมแบบ **Modular Monolith** แบ่ง 4 App ตาม Bounded Context โดยมีทิศทาง Dependency ทางเดียว `catalog` ← `accounts` ← (`materials`, `webboard`) ([ADR 0001](../adr/0001-modular-monolith-and-app-boundaries.md))
   - ทุก App แยกชั้นการทำงานด้วย **Service Layer** และ **Selectors** ([ADR 0002](../adr/0002-service-layer-and-selectors.md))
   - ตารางอนุมัติ (`Approval`, `DocTypeRequiredRole`) และสถิติการดาวน์โหลด (`DownloadLog`) อยู่ในแอป `materials` ตาม [ADR 0004](../adr/0004-approval-tables-in-materials.md)
   - แอป `accounts` จัดการ `User`, `Role`, `UserRole`, การลบบัญชี (`anonymize`, US-13) และนับการจำกัดอัตรา (Rate Limit) ผ่าน Django cache (`accounts/services.py`)
   - วิดเจ็ตชุมชนหน้าแรกอยู่ใน `accounts`: Shoutbox (`ShoutboxMessage`) และโพล (`PollVote`) รับ POST แบบ AJAX จาก `static/js/home_widgets.js` และ query อยู่ใน `accounts/selectors.py`; ตัวนับผู้เข้าชมเก็บใน Django cache; BGM Player ทำงานฝั่ง browser (`static/js/bgm_player.js`)
   - แอป `webboard` จัดการกระดานสนทนาชุมชน (`BoardCategory`, `Thread`, `Post`), ตัวแปลงอีโมติคอน MSN และฝังภาพ `[img]...[/img]` (`webboard/emoticons.py`)
6. **Managed PostgreSQL Database:** ฐานข้อมูลเชิงสัมพันธ์หลักบน Render (Region: Singapore) เชื่อมต่อผ่าน Internal Database URL เพื่อความปลอดภัยและความเร็วสูงสุด
7. **Media Storage (Protected PDF Vault):** ที่จัดเก็บไฟล์เอกสาร PDF จริง โดยยึดหลัก [ADR 0003](../adr/0003-document-storage-and-protected-preview.md) คือ **ไม่ตั้ง `MEDIA_URL`** และไม่มี Direct URL เข้าถึงไฟล์ การเปิดอ่าน (Preview) และดาวน์โหลดต้องผ่านการตรวจสอบสิทธิ์ใน View ของ Django เสมอ
8. **Backup Strategy:** สคริปต์สำรองข้อมูล `scripts/backup_restore.sh` สำหรับทำ Logical Dump (`pg_dump`) และบีบอัดโฟลเดอร์ Media Vault (`tar.gz`) ตามข้อตกลงใน [ADR 0005](../adr/0005-production-deployment-and-backup.md)
