# C4 Model — CNtagram

ไดอะแกรมระดับ 1–2 ของ C4 Model ตาม [`lecture-notes/03`](../lecture-notes/03-software-architecture-and-decomposition.md#การถ่ายทอดสถาปัตยกรรมด้วยแบบจำลอง-c4-model)

## Level 1: System Context Diagram

แสดงขอบเขตของระบบ CNtagram ผู้ใช้งานประเภทต่างๆ และระบบภายนอกที่เกี่ยวข้อง

```mermaid
flowchart LR
    G["👤 Guest<br/>[Person]<br/>ผู้ใช้ทั่วไป ยังไม่ล็อกอิน<br/>ค้นหาและดูตัวอย่างสาธารณะ"]
    S["👤 Student / Alumni<br/>[Person]<br/>นักศึกษาและศิษย์เก่า<br/>ค้นหา อ่าน อัปโหลดชีท"]
    M["👤 Moderator<br/>[Person]<br/>ตัวแทนรุ่น/ผู้ตรวจคัดกรอง<br/>อนุมัติและจัดการชีทของภาค"]
    A["👤 Super Admin<br/>[Person]<br/>ผู้ดูแลระบบส่วนกลาง<br/>จัดการผู้ใช้ สิทธิ์ และภาพรวม"]
    C["👤 อาจารย์ / เจ้าของลิขสิทธิ์<br/>[Person]<br/>ผู้ประสงค์แจ้งลบเนื้อหา"]

    SYS["📚 CNtagram System<br/>[Software System]<br/>เว็บแอปพลิเคชันคลังชีทสรุปและข้อสอบเก่า<br/>คณะวิศวกรรมศาสตร์ มหาวิทยาลัยธรรมศาสตร์<br/>(Deploy บน Render PaaS, Singapore)"]

    MAIL["✉️ Email Service<br/>[External System]<br/>บริการส่งอีเมลแจ้งเตือน/ยืนยันตัวตน<br/>(ยังไม่สร้างใน v1.0.0)"]

    G -- "HTTPS (ชมชีทสาธารณะ)" --> SYS
    S -- "HTTPS (ล็อกอิน, อัปโหลด, ดาวน์โหลด)" --> SYS
    M -- "HTTPS (ตรวจคัดกรอง, อนุมัติเอกสาร)" --> SYS
    A -- "HTTPS (จัดการระบบ, จัดการสิทธิ์)" --> SYS
    C -. "HTTPS (แบบฟอร์มสาธารณะแจ้งลบ - ยังไม่สร้าง)" .-> SYS
    SYS -. "SMTP / REST API (SP-2 - ยังไม่สร้าง)" .-> MAIL
```

### คำอธิบาย System Context (Level 1):
1. **ผู้ใช้งานที่ระบบรองรับจริงในปัจจุบัน (Active Users):**
   - **Guest**: เข้าถึงหน้าแรก ค้นหารายวิชา และดูตัวอย่างเอกสาร (Public Previews)
   - **Student / Alumni**: เข้าสู่ระบบผ่านบัญชีมหาวิทยาลัย อัปโหลดเอกสารใหม่ ดาวน์โหลดไฟล์ และจัดการโปรไฟล์
   - **Moderator**: ตัวแทนนักศึกษาประจำภาควิชาที่ได้รับสิทธิ์ ทำหน้าที่ตรวจคัดกรอง อนุมัติ หรือปฏิเสธเอกสารของภาคตนเอง
   - **Super Admin**: ผู้ดูแลระบบ มีสิทธิ์แต่งตั้ง/ถอดถอน Moderator และเข้าถึง Django Admin
2. **ระบบและส่วนที่ยังไม่ได้สร้างใน v1.0.0 (เส้นประ):**
   - **อาจารย์ / เจ้าของลิขสิทธิ์**: ฟอร์มสาธารณะสำหรับแจ้งละเมิดลิขสิทธิ์ (อยู่นอกขอบเขต MVP v1.0.0)
   - **Email Service**: ระบบส่งอีเมลแจ้งเตือนอัตโนมัติ (ข้ามไปทำในเวอร์ชันถัดไปตามข้อตกลง SP-2)

## Level 2: Container Diagram (Production Architecture)

แสดงสถาปัตยกรรมภายในและเทคโนโลยีที่ใช้จริงบน Production Environment ตามผลการศึกษาใน SP-4 ([ADR 0005](../adr/0005-production-deployment-and-backup.md))

        EDGE["🌐 Edge Router & Reverse Proxy<br/>[Render Infrastructure]<br/>TLS Termination (HTTPS :443), DDoS Shield, HTTP/2"]

### คำอธิบาย Container Level (Level 2):
1. **Web Browser (Client Layer):** ผู้ใช้เข้าชมผ่านเว็บเบราว์เซอร์ด้วยอินเทอร์เฟซ Bootstrap 5 รองรับ Responsive Design บนทุกอุปกรณ์
2. **Render Edge Router / Reverse Proxy:** รับคำขอ HTTPS (Port 443) จากอินเทอร์เน็ต ทำ TLS Termination และส่งต่อคำขอผ่าน Internal Network ไปยังพอร์ต 10000 ของ Web Container
3. **Gunicorn WSGI Server:** ทำหน้าที่เป็น WSGI HTTP Server สำหรับรันโปรเซสของ Django ในสภาพแวดล้อม Production
4. **WhiteNoise Static File Engine:** เสิร์ฟไฟล์คงที่ (CSS, JavaScript, รูปภาพ UI) โดยตรงจาก WSGI Process พร้อมทำ Content Hashing และบีบอัดไฟล์ (Gzip/Brotli) อัตโนมัติ
5. **Django Application & Apps Structure:**
   - สถาปัตยกรรมแบบ **Modular Monolith** แบ่ง App ตาม Bounded Context โดยมีทิศทาง Dependency ทางเดียว `catalog` ← `accounts` ← `materials` ([ADR 0001](../adr/0001-modular-monolith-and-app-boundaries.md))
   - ทุก App แยกชั้นการทำงานด้วย **Service Layer** และ **Selectors** ([ADR 0002](../adr/0002-service-layer-and-selectors.md))
   - ตารางอนุมัติเอกสาร (`MaterialApproval`, `ApprovalLog`) ถูกจัดเก็บไว้ในแอป `materials` ตาม [ADR 0004](../adr/0004-approval-tables-in-materials.md)
6. **Managed PostgreSQL Database:** ฐานข้อมูลเชิงสัมพันธ์หลักบน Render (Region: Singapore) รองรับ Concurrency และ Transaction Integrity
7. **Persistent Disk (Protected PDF Vault):** ที่จัดเก็บไฟล์เอกสาร PDF จริง โดยยึดหลัก [ADR 0003](../adr/0003-document-storage-and-protected-preview.md) คือ **ไม่ตั้ง `MEDIA_URL`** และไม่มี Direct URL เข้าถึงไฟล์ การเปิดอ่าน (Preview) และดาวน์โหลดต้องผ่านการตรวจสอบสิทธิ์ใน View ของ Django เสมอ
8. **Automated Backup Worker:** แผนสำรองข้อมูลอัตโนมัติประจำวัน (Daily Snapshot บน Managed DB ควบคู่กับการทำ Logical Dump ผ่าน `pg_dump`) ตามข้อตกลงใน [ADR 0005](../adr/0005-production-deployment-and-backup.md)
9. **เส้นประ (External Integrations):** ระบบส่งอีเมล (SP-2) และการสแกนไวรัสไฟล์อัปโหลด (SP-1 / US-24) ยังคงเป็นเส้นประเนื่องจากอยู่นอกกรอบเวลาของ v1.0.0
