## 5.2 อภิปรายผล

ประเด็นที่มีข้อมูลรองรับอยู่แล้วและควรอภิปราย (เติมผลจริงให้ครบ):

1. **การเปลี่ยนจาก SRS เป็น Agile Backlog** — ข้อดี (ปรับลำดับได้ทุก Sprint, ไม่เสียเวลาลงรายละเอียด story ที่อาจไม่ได้ทำ) เทียบกับข้อเสีย (ทีมต้องคุยกฎธุรกิจซ้ำก่อนทุก Sprint, เอกสารกระจายระหว่าง repo กับ GitHub issue) **[เติม: สิ่งที่เกิดขึ้นจริง]**
2. **Modular Monolith กับการทำงานขนาน** — ADR 0001 คาดว่าจะลด merge conflict เพราะแบ่งงานตาม app ได้ **[เติม: จำนวน conflict / ปัญหา circular import ที่เจอจริง]**
3. **Service Layer กับการทดสอบ** — ADR 0002 คาดว่าทดสอบกฎธุรกิจได้โดยไม่ผ่าน HTTP **[เติม: coverage ของ services.py เทียบ views.py, ความยากง่ายที่ทีมรู้สึก]**
4. **เก็บกฎเป็นข้อมูล (`doc_type_required_role`, `system_setting`)** — ยืดหยุ่นแต่เพิ่มความซับซ้อน (เช่น ต้องเพิ่ม column `mode` = any/all ถ้าจะเก็บกฎ "อย่างใดอย่างหนึ่ง" ในข้อมูลทั้งหมด)
5. **การบังคับกฎหลายชั้น (DB / Model / Service)** — กฎที่ฐานข้อมูลบังคับไม่ได้ (เช่น partial unique index บน MySQL) ต้องเขียนซ้ำใน model
6. **Velocity และความแม่นยำของการประมาณ** — เปรียบเทียบแต้มที่วางแผนกับที่เสร็จจริงระหว่าง Sprint **[เติม]**
7. **การใช้ AI ช่วยพัฒนา** — ผลของกติกา "ผู้ commit รับผิดชอบ 100% และต้องอธิบายโค้ดได้" **[เติม]**

## 5.4 ข้อเสนอแนะและงานในอนาคต

นำ story/spike ที่กำลังพัฒนาต่อและที่อยู่ใน Backlog ระยะถัดไปจาก [`requirements.md`](../requirements.md) มาสรุปแบ่งตามสถานะ:

### งานที่กำลังพัฒนาและเปิด Pull Request ในโค้งสุดท้าย (In-Progress / Upcoming)
- **E2 โครงสร้างคลัง:** นำเข้าข้อมูลเดิมด้วย CSV พร้อมโหมดทดลองรัน (dry-run) (US-17 / Issue #215, PR #223)
- **E3 แบ่งปันเอกสาร:** ผู้อัปโหลดส่งเวอร์ชันใหม่ แก้คำอธิบาย หรือลบไฟล์ของตัวเอง (US-21 / Issue #217) และช่องเลือกวิชาแบบพิมพ์ค้นหาได้ในหน้าอัปโหลด (Issue #224, PR #225)
- **E4 คัดกรองคุณภาพ:** Moderator และ Super Admin ซ่อนไฟล์ที่เผยแพร่แล้วแต่พบปัญหา (US-25 / Issue #216, PR #227) และปุ่มดาวน์โหลดไฟล์ระหว่างรอพิจารณา (PR #228)
- **E6 ชุมชนและเว็บบอร์ด:** แก้ไขกระทู้/ข้อความตอบกลับพร้อมเวลาแก้ไข (Issue #212), แบ่งหน้า Pagination และกันปั๊มยอดวิว (Issue #211), ปรับปรุงการแปลงอีโมติคอน MSN และ GIF บนมือถือ (Issue #209, #213, PR #222)
- **E7 ลิขสิทธิ์และความไว้วางใจ:** ระบบรายงานเอกสารที่มีปัญหา (US-32 / Issue #218), แบบฟอร์มแจ้งลบเนื้อหาสาธารณะสำหรับเจ้าของลิขสิทธิ์ (US-33 / Issue #219), และหน้าตัดสินเรื่องร้องเรียนของ Super Admin (US-35 / Issue #220)
- **Production & Backup:** ซ้อมกู้คืนฐานข้อมูล PostgreSQL บนฐานข้อมูลแยก (`_restore_test`) และตั้งค่าสำรองข้อมูลรายวันแบบ Offsite (SP-4 / Issue #192, PR #199)
