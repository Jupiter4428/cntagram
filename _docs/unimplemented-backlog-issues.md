## 1. ฟีเจอร์จำเป็นระดับ Must Have (ขาดไม่ได้)

### [US-15] Super Admin นำเข้าไฟล์เดิมจำนวนมากด้วย CSV พร้อมโหมดทดลองรัน
<!-- labels: story, must, backend · milestone: Product Backlog -->

> **สถานะ: Product Backlog** ก่อนดึงเข้า Sprint ต้องผ่าน DoR: ทีมประเมินแต้มด้วย Planning Poker, มีรูปแบบ CSV ที่ตกลงแล้ว, มีผู้รับผิดชอบ
> ถ้าประเมินได้ 13 แต้มขึ้นไป ให้แตกเป็น (1) command + dry run (2) หน้าเว็บอัปโหลด CSV

**As a** Super Admin, **I want** นำเข้าไฟล์เดิมจำนวนมากด้วย CSV พร้อมโหมดทดลองรัน (dry run), **So that** ย้ายข้อมูล CN21–CN25 เข้าระบบได้ครบโดยไม่ต้องอัปโหลดทีละไฟล์

* **Epic:** E2 · **MoSCoW (เสนอ):** Must · **Points (เสนอ):** 8
* **Depends on:** US-4 #26 (รุ่นและวิชาในรุ่น) · US-5 #29 (`upload_document` merge แล้ว)
* **Branch:** `feature/issue-<เลข issue>-bulk-import`

#### เรื่องนี้คืออะไร
ชีทและข้อสอบของ CN21–CN25 อยู่ในไดรฟ์รวมหลายร้อยไฟล์ ถ้าต้องอัปโหลดผ่านฟอร์มทีละไฟล์ คลังจะว่างอยู่นาน story นี้ให้ Super Admin เตรียม CSV (1 แถว = 1 ไฟล์ + ภาค รุ่น วิชา ประเภท ฯลฯ) แล้วสั่งนำเข้าทีเดียว โดยรันแบบ dry run ก่อนเพื่อดูว่าแถวไหนจะพัง โดยไม่เขียนอะไรลง DB หรือ storage

#### ตัวอย่างการใช้งาน
- แอดมินรัน `python manage.py import_documents cn21.csv --files ./drive --dry-run` → เห็นรายงาน "ผ่าน 120 แถว, ผิด 3 แถว: แถว 14 ไม่พบวิชา CN999 ในรุ่น CN21, ..." และ DB ไม่เปลี่ยน
- แก้ CSV แล้วรันโดยไม่มี `--dry-run` → เอกสาร 123 ไฟล์เข้าระบบ
- รันซ้ำไฟล์เดิม → แถวที่นำเข้าแล้วถูกข้าม (เช็กจาก sha256) ไม่เกิดเอกสารซ้ำ

#### Acceptance Criteria
- [ ] นำเข้า CSV ตามรูปแบบที่ตกลง (คอลัมน์ขั้นต่ำ: path ไฟล์, ภาค, เลขรุ่น, รหัสวิชา, ประเภท, ชื่อเอกสาร และช่วงสอบ/ปี พ.ศ. สำหรับข้อสอบ) สร้าง `Document` + `DocumentVersion` (+ `ExamDetail`) ด้วยกฎเดียวกับ US-5 (PDF จริง, ขนาด, path)
- [ ] `--dry-run` ตรวจทุกแถวและรายงานแถวที่ผิดพร้อมเหตุผล โดยไม่เขียน DB และไม่คัดลอกไฟล์
- [ ] แถวที่ผิดไม่ทำให้แถวอื่นพัง หรือถ้าตกลงแบบ all-or-nothing ให้ rollback ทั้งหมดและไม่มีไฟล์กำพร้าค้างใน storage
- [ ] ไฟล์ที่ sha256 ตรงกับไฟล์ที่มีอยู่แล้วถูกข้ามพร้อมรายงาน ผู้ใช้ทั่วไปสั่งนำเข้าไม่ได้

#### ประเด็นที่ต้องคุยก่อนผ่าน DoR
- เผยแพร่ทันที (`published`) หรือเข้าคิวอนุมัติ (`pending`) ถ้าเผยแพร่ทันที ขัดกับกฎ "ผู้อัปโหลดอนุมัติไฟล์ตัวเองไม่ได้" หรือไม่
- `uploader` ของเอกสารที่นำเข้าเป็นใคร (Super Admin ที่สั่ง หรือบัญชีระบบ)
- แถวผิดแล้วข้ามแถว หรือ rollback ทั้งไฟล์
- management command อย่างเดียว หรือต้องมีหน้าเว็บด้วย (เสนอ: command ก่อน)

#### งานย่อย (ทีมแตกเพิ่มเองตอน Sprint Planning)
- [ ] ตกลงรูปแบบ CSV + ไฟล์ตัวอย่างใน `_docs/`
- [ ] service นำเข้า (แยกตรวจแถวกับเขียนจริง ให้ dry run ใช้ตัวตรวจเดียวกัน) ใน `materials/services.py` ใช้ `_validate_pdf` / `_storage_path` เดิม
- [ ] management command `import_documents` + รายงานผล
- [ ] test: dry run ไม่เขียน DB/storage, แถวผิดแต่ละแบบ, ไฟล์ซ้ำถูกข้าม, rollback ไม่ทิ้งไฟล์กำพร้า

#### จุดที่ต้องแก้
- `materials/services.py` ฟังก์ชัน `upload_document` แยกส่วนตรวจ PDF, คำนวณ sha256 และ storage path ออกมาเป็น Helper สำหรับ Bulk Import
- `materials/models.py` เรียกใช้ `Document.add_version`
- สร้าง Management Command ใน `materials/management/commands/import_documents.py`

### [US-23] Moderator และ Super Admin ซ่อนไฟล์ที่เผยแพร่แล้วแต่มีปัญหา
<!-- labels: story, must, backend, frontend · milestone: Product Backlog -->

**As a** Moderator / Super Admin, **I want** ซ่อนไฟล์ที่เผยแพร่แล้วแต่มีปัญหาพร้อมบันทึกเหตุผล, **So that** คลังมีแต่เอกสารที่ถูกต้องและปลอดภัย

* **Epic:** E4 (กำกับดูแล) · **MoSCoW:** Must · **Points (เสนอ):** 3
* **Branch:** `feature/issue-<เลข issue>-hide-document`

#### เรื่องนี้คืออะไร
ในโค้ดปัจจุบัน โมเดล `Document` มีสถานะ `Document.Status.HIDDEN` แล้ว และหน้าค้นหาใน `selectors.py` ก็ exclude สถานะนี้ออกแล้ว แต่ยังไม่มี endpoint / service / UI ให้ Moderator หรือ Super Admin กดสั่งซ่อนเอกสารเมื่อพบว่ามีปัญหาเรื่องลิขสิทธิ์หรือข้อสอบหลุด

#### Acceptance Criteria
- [ ] Moderator (เฉพาะภาคของตน) และ Super Admin (ทุกภาค) สามารถสั่งซ่อนเอกสารที่สถานะเป็น `published` ได้ พร้อมระบุเหตุผลในการซ่อน
- [ ] เอกสารที่สถานะเป็น `hidden` จะไม่ปรากฏในหน้าค้นหา และผู้ใช้ทั่วไปเข้าถึงผ่าน URL ตรงหรือ Preview ตรงไม่ได้ (ตอบ 404)
- [ ] การสั่งซ่อนต้องเปลี่ยนสถานะผ่าน Service ที่รันภายใน Database Transaction เดียวกัน

#### จุดที่ต้องแก้
- `materials/models.py` มี `Status.HIDDEN` อยู่แล้ว
- `materials/services.py` เพิ่ม service `hide_document(*, document, user, reason)`
- `materials/views.py` เพิ่ม action view และปุ่มบนหน้า document สำหรับ Moderator/Admin

## 2. ฟีเจอร์สำคัญสูงระดับ Should Have

### [US-19] ผู้อัปโหลดส่งเวอร์ชันใหม่ แก้คำอธิบาย หรือลบไฟล์ของตัวเอง
<!-- labels: story, should, backend, frontend · milestone: Product Backlog -->

> **สถานะ: Product Backlog** ก่อนดึงเข้า Sprint ต้องผ่าน DoR: ทีมประเมินแต้มด้วย Planning Poker, มี mockup, มีผู้รับผิดชอบ
> ถ้าประเมินได้ 13 แต้มขึ้นไป ให้แตกเป็น (1) แก้คำอธิบาย + ลบ (2) ส่งเวอร์ชันใหม่

**As a** ผู้อัปโหลด, **I want** ส่งไฟล์เวอร์ชันใหม่ แก้คำอธิบาย หรือลบไฟล์ของตัวเอง, **So that** ชีทของฉันถูกต้องและทันสมัย

* **Epic:** E3 · **MoSCoW (เสนอ):** Should · **Points (เสนอ):** 5
* **Depends on:** US-5 #29 (merge แล้ว) · US-34 #34 (รายการ "ไฟล์ของฉัน" เป็นจุดเข้าหน้าจัดการ)
* **Branch:** `feature/issue-<เลข issue>-manage-own-document`

#### เรื่องนี้คืออะไร
หลังอัปโหลด ผู้อัปโหลดแก้อะไรไม่ได้เลย ถ้าพบจุดผิดในชีทต้องอัปโหลดเป็นเอกสารใหม่ ทำให้คลังมีชีทซ้ำหลายฉบับ `DocumentVersion` และ `Document.add_version()` รองรับหลายเวอร์ชันอยู่แล้ว story นี้เพิ่มหน้าให้เจ้าของเอกสารส่งเวอร์ชันใหม่ แก้ชื่อ/คำอธิบาย และลบเอกสารของตัวเอง

#### ตัวอย่างการใช้งาน
- ต้นเปิดเอกสาร "CN200 สรุป midterm" ของตัวเอง → อัปโหลด PDF ฉบับแก้ → ได้เวอร์ชัน 2
- ต้นแก้คำอธิบายเป็น "แก้สูตรหน้า 3 แล้ว" → บันทึกได้ทันที
- ต้นกดลบเอกสาร → เอกสารหายจากคลังและจากรายการของต้น
- เพื่อนของต้นส่งคำขอแก้เอกสารของต้น → 403

#### Acceptance Criteria
- [ ] เจ้าของเอกสารส่ง PDF เวอร์ชันใหม่ได้ด้วยกฎเดียวกับ US-5 (PDF จริง, ขนาด) ได้ `version_no` ถัดไป และหน้าเอกสาร/preview แสดงเวอร์ชันล่าสุด
- [ ] เจ้าของเอกสารแก้ชื่อและคำอธิบายได้
- [ ] เจ้าของเอกสารลบเอกสารของตัวเองได้หลังยืนยัน เอกสารที่ลบแล้วไม่อยู่ในผลค้นหาและหน้าเอกสารตอบ 404
- [ ] ผู้ใช้อื่นแก้/ลบ/ส่งเวอร์ชันใหม่ให้เอกสารที่ไม่ใช่ของตัวเองไม่ได้ (403)

#### ประเด็นที่ต้องคุยก่อนผ่าน DoR
- เวอร์ชันใหม่ของไฟล์ที่ `published` แล้ว ต้องรออนุมัติใหม่หรือไม่ ระหว่างรอ ผู้ใช้เห็นเวอร์ชันเก่าหรือไม่เห็นเลย
- ข้อสอบที่เผยแพร่แล้วผู้อัปโหลดลบเองได้ไหม
- "ลบ" คือลบจริง (ไฟล์ + แถว) หรือ soft delete (เปลี่ยนสถานะ)
- แก้ชื่อ/คำอธิบายของไฟล์ที่ `published` แล้วต้องรออนุมัติไหม

#### งานย่อย (ทีมแตกเพิ่มเองตอน Sprint Planning)
- [ ] service `add_document_version` / `update_document_info` / `delete_document` (ตรวจความเป็นเจ้าของ, `select_for_update`) ใน `materials/services.py`
- [ ] Form + view บาง + หน้าจัดการเอกสารของตัวเอง (layout FE-1)
- [ ] test: แต่ละ action สำเร็จ, คนอื่น 403, เวอร์ชันใหม่ผิดกฎ PDF, ลบแล้ว 404, สถานะหลังส่งเวอร์ชันใหม่ตามที่ตกลง

#### จุดที่ต้องแก้
- `materials/models.py` `add_version` และ `current_version`
- `materials/services.py` เพิ่มฟังก์ชัน update / delete / add_version
- `materials/views.py` หน้า `document_detail` วางปุ่มจัดการเฉพาะเจ้าของ

### [US-31] ผู้ใช้รายงานเอกสารที่มีปัญหา
<!-- labels: story, should, backend, frontend · milestone: Product Backlog -->

> **สถานะ: Product Backlog** ก่อนดึงเข้า Sprint ต้องผ่าน DoR: ทีมประเมินแต้มด้วย Planning Poker, มี mockup, มีผู้รับผิดชอบ

**As a** ผู้ใช้, **I want** รายงานเอกสารที่มีปัญหา (ละเมิดลิขสิทธิ์, ข้อสอบที่ห้ามเผยแพร่, เนื้อหาผิด), **So that** ผู้ดูแลรู้และจัดการได้

* **Epic:** E7 · **MoSCoW (เสนอ):** Should · **Points (เสนอ):** 3
* **Depends on:** US-7 #31 (หน้าเอกสาร) · US-23 (ซ่อนไฟล์)
* **Branch:** `feature/issue-<เลข issue>-report-document`

#### เรื่องนี้คืออะไร
ถ้านักศึกษาเจอข้อสอบที่อาจารย์ห้ามเผยแพร่ หรือชีทที่ลอกหนังสือทั้งเล่ม ตอนนี้ไม่มีปุ่มแจ้ง story นี้เพิ่มปุ่ม "รายงาน" บนหน้าเอกสาร เก็บลงตาราง `report` ตาม database-design §3.5 และให้ Moderator ของภาค / Super Admin เห็นรายการรายงานที่ยังเปิดอยู่

#### Acceptance Criteria
- [ ] ผู้ใช้ที่ล็อกอินแล้วรายงานเอกสาร `published` ได้ ต้องเลือกประเภท (ลิขสิทธิ์ / ข้อสอบห้ามเผยแพร่ / เนื้อหาผิด / อื่น ๆ) และใส่เหตุผล รายงานถูกสร้างด้วยสถานะ `open`
- [ ] ผู้ใช้คนเดิมรายงานเอกสารเดิมซ้ำขณะรายงานเดิมยัง `open` ไม่ได้
- [ ] Moderator เห็นรายงานที่ `open` ของภาคตัวเอง Super Admin เห็นทั้งหมด ผู้ใช้ทั่วไปเปิดรายการนี้ → 403
- [ ] ตัวตนผู้รายงานไม่แสดงต่อผู้อัปโหลด

#### จุดที่ต้องแก้
- `materials/models.py` เพิ่มโมเดล `Report`
- `materials/services.py` เพิ่ม `report_document`
- `materials/views.py` วางปุ่มรายงานบนหน้า `document_detail`

### [US-32] เจ้าของลิขสิทธิ์ที่ไม่มีบัญชีแจ้งลบเนื้อหาผ่านแบบฟอร์มสาธารณะ

> **สถานะ: Product Backlog** ก่อนดึงเข้า Sprint ต้องผ่าน DoR: ทีมประเมินแต้มด้วย Planning Poker, มี mockup, มีผู้รับผิดชอบ

**As a** อาจารย์/เจ้าของลิขสิทธิ์ที่ไม่มีบัญชี, **I want** แจ้งลบเนื้อหาผ่านแบบฟอร์มสาธารณะ, **So that** งานของฉันถูกนำลงจากระบบ

* **Epic:** E7 · **MoSCoW (เสนอ):** Should · **Points (เสนอ):** 5
* **Depends on:** US-31 (ตารางรายงาน)
* **Branch:** `feature/issue-<เลข issue>-takedown-form`

#### เรื่องนี้คืออะไร
อาจารย์ไม่มีบัญชีในระบบ (สมัครได้เฉพาะ `@student.tu.ac.th`) และเปิดดูเอกสารไม่ได้ แต่ต้องแจ้งลบงานของตัวเองได้ตามข้อจำกัดด้านลิขสิทธิ์ story นี้เพิ่มแบบฟอร์มที่ Guest เปิดได้ (ลิงก์จาก footer และหน้าแรก) เก็บคำขอให้ Super Admin ตรวจใน US-33

#### Acceptance Criteria
- [ ] Guest เปิดแบบฟอร์มได้โดยไม่ต้องล็อกอิน (เป็นหน้าเดียวที่ยกเว้นจากการบล็อก Guest) ส่งแล้วได้หมายเลขอ้างอิง
- [ ] ช่องบังคับ: ชื่อ, อีเมลติดต่อ, ข้อมูลระบุเนื้อหา (รหัสวิชา/ชื่อเอกสาร/ลิงก์), เหตุผล และการยืนยันว่าเป็นเจ้าของลิขสิทธิ์ ช่องผิดแจ้งเป็นภาษาไทย
- [ ] แบบฟอร์มมี CSRF และ rate limit ต่อ IP แบบเดียวกับหน้าสมัคร
- [ ] คำขอถูกเก็บและแสดงในรายการเรื่องร้องเรียนของ Super Admin โดยไม่เปิดเผยรายชื่อเอกสารในคลังแก่ Guest

#### จุดที่ต้องแก้
- `materials/models.py` โมเดลเก็บคำขอแจ้งลบ (หรือฟิลด์สำหรับบุคคลภายนอกใน `Report`)
- `materials/services.py` เพิ่ม service `submit_takedown_request` พร้อม Rate Limit
- `templates/` เพิ่มหน้าแบบฟอร์มสาธารณะและปุ่มลิงก์จาก footer

### [US-33] Super Admin ตรวจเรื่องร้องเรียนแล้วตัดสิน
<!-- labels: story, should, backend, frontend · milestone: Product Backlog -->

> **สถานะ: Product Backlog** ก่อนดึงเข้า Sprint ต้องผ่าน DoR: ทีมประเมินแต้มด้วย Planning Poker, มี mockup, มีผู้รับผิดชอบ

**As a** Super Admin, **I want** ตรวจเรื่องร้องเรียนแล้วตัดสิน (ลบ, คืนสถานะ, ให้แก้ไข), **So that** ข้อพิพาทลิขสิทธิ์จบได้อย่างโปร่งใส

* **Epic:** E7 · **MoSCoW (เสนอ):** Should · **Points (เสนอ):** 5
* **Depends on:** US-31 (รายงาน) · US-32 (คำขอจากภายนอก) · US-23 (ซ่อนไฟล์)
* **Branch:** `feature/issue-<เลข issue>-resolve-reports`

#### เรื่องนี้คืออะไร
US-31 และ US-32 เก็บเรื่องร้องเรียนไว้ แต่ยังไม่มีขั้นตอนตัดสิน story นี้ให้ Super Admin เปิดเรื่อง ดูเอกสาร แล้วเลือกผล: นำลง (ซ่อน/ลบ), คืนสถานะ (ยกคำร้อง), หรือให้ผู้อัปโหลดแก้ไข ทุกการตัดสินมีเหตุผล บันทึกย้อนหลังได้ เป้าตั้งต้นคือตัดสินภายใน ~72 ชั่วโมง

#### Acceptance Criteria
- [ ] Super Admin เห็นรายการเรื่องร้องเรียนทั้งหมด (จากผู้ใช้และจากภายนอก) กรองตามสถานะ และเห็นอายุของเรื่อง เรื่องที่เกิน 72 ชั่วโมงถูกเน้น
- [ ] Super Admin ตัดสินได้ 3 แบบ (นำลง / ยกคำร้อง / ให้แก้ไข) ต้องใส่เหตุผล ผลถูกบันทึก (`handled_by`, `resolved_at`) และเอกสารเปลี่ยนสถานะตามผลใน transaction เดียวกัน
- [ ] ผู้ใช้ที่ไม่ใช่ Super Admin เปิดหน้าตัดสินไม่ได้ (403)

#### จุดที่ต้องแก้
- `materials/services.py` เพิ่ม `resolve_report` สั่งเปลี่ยนสถานะเอกสาร
- `materials/views.py` เพิ่มหน้ารายการเรื่องร้องเรียนและหน้าตัดสินสำหรับ Super Admin
